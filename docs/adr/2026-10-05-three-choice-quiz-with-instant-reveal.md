# 3択クイズ・1問ごとの即時判定・ジャミーンによる演出への変更

## 背景

当初は「不祥事の有無」を右/左スワイプで答え、10問まとめて採点する設計だった
（`2026-10-05-tech-stack-and-server-side-grading.md`）。
その後、次の要望が出た。

- 選択肢を 善人 / 犯罪者 / 不祥事（犯罪ではない）の3択にする
- 案内役の少女キャラ「ジャミーン」に写真を見せる UI にする
- 回答の直後に正解を発表する
- 正解はジャミーンの表情（善人=笑顔、犯罪者=顔を隠して嫌がる、不祥事=浮かない顔）で表現するため、
  正解/不正解は顔とは別の情報として表示する

## 決定内容

- `celebrities.has_scandal`（boolean）を `celebrities.category`（`good` / `criminal` / `scandal`）に置き換える。
  未リリースのためマイグレーションは作り直した（`migrations/0000_init.sql` を再生成）
- 分類の定義は `src/shared/category.ts` に置き、DBスキーマ・サーバー・画面で共有する
- 採点方式を変更する:
  - `getQuiz`: 出題用。正解は返さない（従来どおり）
  - `checkAnswer`（新規）: 1問ごとに、その芸能人1人分の正解・解説だけを返す
  - `gradeQuiz`（まとめて採点）は廃止
  - `submitScore`: 従来どおり、回答一覧を受け取りサーバー側で再採点して保存する（クライアントの点数は信用しない）
- 画面は、スワイプ UI（`SwipeDeck`）を廃止し、`QuizPlayer`（3択ボタン + 写真 + ジャミーン）に置き換える
- ジャミーンはオリジナルの SVG イラスト（`Jameen.tsx`）。表情は正解カテゴリで決め、
  正解/不正解は別パネル（`RevealPanel`）に大きく表示する

## 理由

- 即時発表のため、回答のたびにサーバーで判定する必要がある。クライアントに全問の正解を持たせない方針は維持できる
- 表情が正解カテゴリそのものを表すので、ジャミーンの顔だけでは本人の正誤が分からない。
  そのため正誤は顔とは独立したパネルで示す必要がある
- 実在の俳優の写真・顔は使わず、特徴（長い黒髪・白い髪飾り・赤い襟の民族衣装）を借りたオリジナルのイラストにした

## 却下した選択肢

- 全問の正解を最初にクライアントへ送って即時判定: 通信は減るが、開発者ツールで全問正解できてしまう
- `has_scandal` を残して `is_crime` 列を追加: 「犯罪なのに不祥事なし」のような矛盾した組み合わせを許してしまう。列挙型1つのほうが整合性を保ちやすい
- 既存DBに ALTER で移行するマイグレーションを追加: 本番未デプロイで移行すべきデータがないため、作り直したほうが履歴が単純

## 影響

- 回答済みの問題は正解が画面上で分かるため、同じクイズを再プレイすると満点を取りやすい。
  ランキングの公平性は「新しいクイズセットを追加し続ける」運用で担保する
- 回答のたびにサーバーへ問い合わせるため、1プレイあたりのリクエスト数が増える（D1 の読み取りは軽量）
- 以前のランキングの `scores` は、旧マイグレーション破棄とともに失われている（未リリースのため問題なし）
